Interface en ligne de commande

nextcloudcmd synchronise un répertoire local avec un serveur Nextcloud, puis quitte. Il peut reprendre des synchronisations ensuite si besoin mais il ne surveille pas les fichiers locaux en continu ni n’interroge le serveur pour d’éventuelles modifications contrairement à l’application de bureau. Pour les options passées à la commande nextcloud de l’application de bureau, reportez-vous aux Command-line options.

Installation

Installez un paquet qui fournit nextcloudcmd. Sa disponibilité dépend de votre système d’exploitation et du paquet :

Source du paquet

Utilisation

Utilisez un répertoire local existant et l’URL de base du serveur Nextcloud :

nextcloudcmd [options] local_directory server_url

Par exemple, synchronisez le dossier distant Music vers un dossier local existant :

nextcloudcmd --user carla --path /Music "$HOME/media/music" https://cloud.example.com

Le client demande le mot de passe. Vous pouvez utiliser un mot de passe d’application venant des paramètres de sécurité de votre compte Nextcloud. N’ajoutez pas de point de terminaison WebDAV à l’URL du serveur ; utilisez --path dans le cas d’un sous-dossier distant.

Exécutez nextcloudcmd sans argument pour afficher son aide, ou nextcloudcmd --version pour afficher sa version. Les options avec des valeurs acceptent aussi bien --option valeur que --option=valeur.

Options

Paramètre

Par défaut

Description

--path <path>

Racine du serveur

Synchroniser un sous-dossier distant, par exemple /Documents.

--user <user>, -u <user>

Voir les identifiants plus bas

Nom pour la connexion. Remplace le nom d’utilisateur dans l’URL du serveur.

--password <password>, -p <password>

Voir les identifiants plus bas

Mot de passe ou mot de passe d’application. Remplace le mot de passe spécifié dans l’URL du serveur. Les mots de passe en ligne de commande peuvent être visibles en listant les processus et en consultant l’historique de l’interpréteur de commandes.

-n

Non défini

Lire les identifiants depuis l’entrée par défaut ou de l’hôte correspondant du fichier .netrc. Ils remplacent ceux spécifiés dans l’URL ou avec --user et --password.

--non-interactive

Non défini

Ne pas demander d’identifiants. Lire les identifiants manquants à partir de NC_USER et NC_PASSWORD.

--silent, -s

Non défini

Supprimer les messages de journalisation de Qt. Ne supprime pas tous les messages de la console.

--trust

Non défini

Accepter les certificats TLS non fiables. À n’utiliser que pour une exécution de diagnostics sous contrôle ; en temps normal, corrigez la configuration de confiance des certificats.

--httpproxy <url>

Pas de proxy explicite

Définir un proxy HTTP en utilisant http://nomhote:port. Cette option n’analyse pas les identifiants de proxy dans l’URL.

--exclude <file>

Liste d’exclusion du système

Ajouter une liste d’exclusion. Le fichier doit exister. Le motif est ancré en fonction de son nom de fichier ; voir Listes d’exclusion.

--exclude-anchored <file>

Non défini

Ajouter une liste d’exclusion avec les motifs ancrés sur la racine de la synchronisation, indépendamment du nom de fichier.

--unsyncedfolders <file>

Non défini

Lire les dossiers distants à exclure de la synchronisation, un chemin relatif par ligne. Les lignes vides et celles commençant par # sont ignorées.

--max-sync-retries <number>

3

Nombre maximal de relances à exécuter quand le moteur de synchronisation demande une autre synchronisation. Ce n’est pas le nombre de nouvelles tentatives global en cas d’échec d’une requête.

--uplimit <number>

0 Ko/s

Limite de débit montant en ko/s (1000 octets par seconde). Zéro signifie qu’il n’y a pas de limite.

--downlimit <number>

0 Ko/s

Limite de débit descendant en ko/s (1000 octets par seconde). Zéro signifie qu’il n’y a pas de limite.

-h

Les fichiers cachés sont inclus

Inclure les fichiers cachés. Il s’agit déjà du réglage par défaut ; -h n’affiche pas l’aide.

--logdebug

Non défini

Activer la journalisation de débogage de Nextcloud et envoyer la sortie des journaux sur la sortie standard.

--confdir <directory>

Emplacement standard

Utiliser un répertoire de configuration différent. Cette option ne fait pas hériter la synchronisation ponctuelle de tous les paramètres de synchronisation du bureau.

--version, -v

Non demandé

Afficher les informations de version et quitter. Exécutez cette option sans les arguments du répertoire et du serveur.

Gestion des identifiants

Les identifiants sont lus dans cet ordre :

  1. Le nom d’utilisateur et le mot de passe dans l’URL du serveur, s’ils sont fournis.

  2. --user et --password, lesquels remplacent les valeurs correspondantes de l’URL.

  3. Une entrée par défaut ou d’hôte correspondant du fichier .netrc quand -n est utilisé, laquelle remplace les deux valeurs.

  4. Saisies pour toute valeur manquante, ou les variables d’environnement ci-dessous quand --non-interactive est utilisé.

Privilégiez une demande de mot de passe ou un fichier .netrc protégé plutôt que mettre les mots de passe dans une commande ou une URL.

Paramètre

Par défaut

Description

NC_USER

Non défini

Nom d’utilisateur par défaut pour une synchronisation ponctuelle avec --non-interactive. Utilisé seulement si aucun nom d’utilisateur n’a été renseigné par l’une des méthodes précédentes.

NC_PASSWORD

Non défini

Mot de passe par défaut pour une synchronisation ponctuelle avec --non-interactive. Utilisé seulement si aucun mot de passe n’a été renseigné par l’une des méthodes précédentes.

Ces variables ne fournissent pas les identifiants pour le mode de configuration de compte décrit plus bas. Pour les redéfinitions des paramètres de transfert, lesquels sont partagés avec le moteur de synchronisation de bureau, voir Environment variables. nextcloudcmd utilise une taille de bloc initiale de 100 Mio, avec un minimum de 5 Mo, un maximum de 5 Go et 6 tâches en parallèle à moins que ce ne soit redéfinit par ces variables. Les paramètres de taille de bloc ne sont pas lus depuis le fichier nextcloud.cfg de l’application de bureau.

Listes d’exclusion

Le client charge la liste d’exclusion système lorsqu’elle est disponible. Vous pouvez ajouter votre propre liste avec --exclude ou --exclude-anchored. Une erreur est générée si un fichier explicitement fourni est manquant.

Avec --exclude, un fichier nommé sync-exclude.lst utilise la racine de la synchronisation pour la correspondance des motifs. Les autres noms de fichier peuvent utiliser le répertoire du fichier d’exclusion comme base. Utilisez --exclude-anchored quand le nom du fichier et l’emplacement ne doivent pas affecter la correspondance.

Entrez un motif par ligne. Les caractères génériques sont pris en charge, par exemple :

*.tmp
._*
Thumbs.db

Configuration de compte

nextcloudcmd peut aussi enregistrer un compte pour qu’il soit utilisé par l’application de bureau. La présence de --userid sélectionne ce mode ; n’indiquez pas le répertoire local de position ni l’URL du serveur qui servent à la synchronisation ponctuelle. La commande quitte une fois la configuration terminée.

Paramètre

Par défaut

Description

--userid <user>

Requis

ID utilisateur du compte à créer.

--serverurl <url>

Requis

URL de base du serveur Nextcloud, par exemple https://cloud.exemple.com.

--apppassword <password>

Non défini

Mot de passe de l’application pour le compte. S’il est omis, le compte est enregistré et vous devez vous connecter à l’application de bureau plus tard.

--localdirpath <path>

Dossier suggéré

Dossier local de synchronisation. S’il est omis, le dossier suggéré par l’assistant de configuration est utilisé. Un dossier existant doit être vide. Ignoré quand le mode File Provider de macOS est activé.

--remotedirpath <path>

/

Dossier distant pour la nouvelle connexion de synchronisation classique. S’applique quand un dossier local de synchronisation est créé.

--isvfsenabled <0|1>

0

Utiliser 1 pour demander des fichiers virtuels avec la nouvelle synchronisation classique de dossiers quand c’est pris en charge, ou 0 pour télécharger les fichiers. Cette option n’active pas le mode File Provider de macOS.

Par exemple, enregistrer un compte et se connecter ensuite depuis l’application de bureau :

nextcloudcmd --userid carla --serverurl https://cloud.example.com --localdirpath "$HOME/Nextcloud"
