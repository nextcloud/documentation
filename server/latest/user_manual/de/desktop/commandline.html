Befehlszeilen-Client

nextcloudcmd synchronisiert ein lokales Verzeichnis mit einem Nextcloud-Server und beendet sich dann. Bei Bedarf kann es Folgesynchronisierungen durchführen, überwacht aber nicht wie die Desktop-App fortlaufend lokale Dateien oder fragt den Server nach Änderungen ab. Optionen für den Befehl nextcloud der Desktop-App finden Sie unter Befehlszeilenoptionen.

Installation

Installieren Sie ein Paket, das nextcloudcmd bereitstellt. Die Verfügbarkeit hängt von Ihrem Betriebssystem und Paket ab:

Betriebssystem

Paketquelle

Alpine Linux

nextcloud-client

Debian

nextcloud-desktop-cmd

Fedora

nextcloud-client

Ubuntu

nextcloud-desktop-cmd

Ubuntu PPA

Nextcloud-Client PPA

Windows

Nextcloud-Downloads

Verwendung

Verwenden Sie ein vorhandenes lokales Verzeichnis und die Basis-URL des Nextcloud-Servers:

nextcloudcmd [options] local_directory server_url

Synchronisieren Sie zum Beispiel den entfernten Ordner Music in einen vorhandenen lokalen Ordner:

nextcloudcmd --user carla --path /Music "$HOME/media/music" https://cloud.example.com

Der Client fragt nach dem Passwort. Sie können ein App-Passwort aus den Sicherheitseinstellungen Ihres Nextcloud-Kontos verwenden. Hängen Sie keinen WebDAV-Endpunkt an die Server-URL an; verwenden Sie --path für einen entfernten Unterordner.

Führen Sie nextcloudcmd ohne Argumente aus, um die Hilfe anzuzeigen, oder nextcloudcmd --version, um die Version anzuzeigen. Optionen mit Werten akzeptieren sowohl --option value als auch --option=value.

Optionen

Parameter

Standard

Beschreibung

--path <path>

Server-Root

Einen externen Unterordner, zum Beispiel /Dokumente synchronisieren.

--user <user>, -u <user>

Siehe Anmeldeinformationen unten

Anmeldename. Überschreibt den Benutzernamen in der Server-URL.

--password <password>, -p <password>

Siehe Anmeldeinformationen unten

Passwort oder App-Passwort. Überschreibt das Passwort in der Server-URL. Auf der Befehlszeile angegebene Passwörter können in Prozesslisten und im Shell-Verlauf sichtbar sein.

-n

Nicht gesetzt

Zugangsdaten aus einem passenden Host- oder Standardeintrag in .netrc lesen. Diese ersetzen Zugangsdaten, die in der URL oder mit --user und --password angegeben wurden.

--non-interactive

Nicht gesetzt

Nicht nach Zugangsdaten fragen. Fehlende Zugangsdaten aus NC_USER und NC_PASSWORD lesen.

--silent, -s

Nicht gesetzt

Qt-Protokollmeldungen unterdrücken. Unterdrückt nicht alle Konsolenmeldungen.

--trust

Nicht gesetzt

Nicht vertrauenswürdige TLS-Zertifikate akzeptieren. Nur für einen kontrollierten Diagnoselauf verwenden; normalerweise sollte die Konfiguration des Zertifikatsvertrauens korrigiert werden.

--httpproxy <url>

Kein expliziter Proxy

Einen HTTP-Proxy mit http://hostname:port festlegen. Diese Option wertet keine Proxy-Zugangsdaten in der URL aus.

--exclude <file>

Systemausschlussliste

Eine Ausschlussliste hinzufügen. Die Datei muss existieren. Die Verankerung der Muster hängt vom Dateinamen ab; siehe Listen ausschließen.

--exclude-anchored <file>

Nicht gesetzt

Eine Ausschlussliste hinzufügen, deren Muster unabhängig vom Dateinamen am Synchronisierungsstamm verankert sind.

--unsyncedfolders <file>

Nicht gesetzt

Entfernte Ordner lesen, die von der Synchronisierung ausgeschlossen werden sollen, ein relativer Pfad pro Zeile. Leere Zeilen und Zeilen, die mit # beginnen, werden ignoriert.

--max-sync-retries <number>

3

Maximale Anzahl von Folgedurchläufen, wenn die Synchronisierungs-Engine eine weitere Synchronisierung anfordert. Dies ist keine allgemeine Anzahl von Wiederholungen für jede fehlgeschlagene Anfrage.

--uplimit <number>

0 KB/s

Begrenzung der Upload-Geschwindigkeit in KB/s (1000 Bytes pro Sekunde). Null bedeutet unbegrenzt.

--downlimit <number>

0 KB/s

Begrenzung der Download-Geschwindigkeit in KB/s (1000 Bytes pro Sekunde). Null bedeutet unbegrenzt.

-h

Verborgene Dateien eingeschlossen

Versteckte Dateien einbeziehen. Dies ist bereits die Standardeinstellung; -h zeigt keine Hilfe an.

--logdebug

Nicht gesetzt

Nextcloud-Debug-Protokollierung aktivieren und Protokollausgaben auf die Standardausgabe schreiben.

--confdir <directory>

Standartort

Ein anderes Konfigurationsverzeichnis verwenden. Dadurch übernimmt die einmalige Synchronisierung nicht alle Synchronisierungseinstellungen der Desktop-App.

--version, -v

Nicht angefordert

Versionsinformationen anzeigen und beenden. Führen Sie diese Option ohne die Argumente für Verzeichnis und Server aus.

Anmeldeinformationsverwaltung

Anmeldeinformationen werden in dieser Reihenfolge gelesen:

  1. Benutzername und Passwort in der Server-URL, falls angegeben.

  2. --user und --password, die die entsprechenden Werte aus der URL ersetzen.

  3. Ein passender Host- oder Standardeintrag in .netrc, wenn -n verwendet wird; dieser ersetzt beide Werte.

  4. Abfragen für alle fehlenden Werte oder, wenn --non-interactive verwendet wird, die unten aufgeführten Umgebungsvariablen.

Bevorzugen Sie eine Passwortabfrage oder eine geschützte .netrc-Datei, statt Passwörter in einen Befehl oder eine URL zu schreiben.

Parameter

Standard

Beschreibung

NC_USER

Nicht gesetzt

Ersatzwert für den Benutzernamen bei einer einmaligen Synchronisierung mit --non-interactive. Wird nur verwendet, wenn mit den vorhergehenden Methoden kein Benutzername angegeben wurde.

NC_PASSWORD

Nicht gesetzt

Ersatzwert für das Passwort bei einer einmaligen Synchronisierung mit --non-interactive. Wird nur verwendet, wenn mit den vorhergehenden Methoden kein Passwort angegeben wurde.

Diese Variablen liefern keine Zugangsdaten für den unten beschriebenen Kontoeinrichtungsmodus. Übertragungseinstellungen, die mit der Synchronisierungs-Engine der Desktop-App geteilt werden, finden Sie unter Umgebungsvariablen. nextcloudcmd verwendet eine anfängliche Chunk-Größe von 100 MiB, ein Minimum von 5 MB, ein Maximum von 5 GB und 6 parallele Aufträge, sofern diese Variablen nichts anderes festlegen. Die Chunk-Größen-Einstellungen der Desktop-App aus nextcloud.cfg werden nicht gelesen.

Listen ausschließen

Der Client lädt die System-Ausschlussliste, sofern verfügbar. Mit --exclude oder --exclude-anchored können Sie eine eigene Liste hinzufügen. Eine ausdrücklich angegebene, aber fehlende Datei führt zu einem Fehler.

Bei --exclude verwendet eine Datei namens sync-exclude.lst den Synchronisierungsstamm für den Musterabgleich. Andere Dateinamen können das Verzeichnis der Ausschlussdatei als Basis verwenden. Verwenden Sie --exclude-anchored, wenn Dateiname und Speicherort den Abgleich nicht beeinflussen sollen.

Schreiben Sie ein Muster pro Zeile. Platzhalter werden unterstützt, zum Beispiel:

*.tmp
._*
Thumbs.db

Kontoeinstellungen

nextcloudcmd kann außerdem ein Konto für die Verwendung durch die Desktop-App speichern. Die Angabe von --userid wählt diesen Modus; lassen Sie das lokale Verzeichnis und die Server-URL weg, die als Positionsargumente für eine einmalige Synchronisierung verwendet werden. Der Befehl beendet sich nach Abschluss der Einrichtung.

Parameter

Standard

Beschreibung

--userid <user>

Erforderlich

Benutzer-ID für das zu erstellende Konto.

--serverurl <url>

Erforderlich

Basis-URL des Nextcloud-Servers, zum Beispiel https://cloud.example.com.

--apppassword <password>

Nicht gesetzt

App-Passwort für das Konto. Wird es weggelassen, wird das Konto gespeichert und Sie müssen sich später in der Desktop-App anmelden.

--localdirpath <path>

Vorgeschlagener Ordner

Lokaler Synchronisierungsordner. Wird er weggelassen, wird der vom Einrichtungsassistenten vorgeschlagene Ordner verwendet. Ein vorhandener Ordner muss leer sein. Wird ignoriert, wenn der macOS-File-Provider-Modus aktiviert ist.

--remotedirpath <path>

/

Entfernter Ordner für die neue klassische Synchronisierungsverbindung. Gilt, wenn ein lokaler Synchronisierungsordner erstellt wird.

--isvfsenabled <0|1>

0

Verwenden Sie 1, um für den neuen klassischen Synchronisierungsordner virtuelle Dateien anzufordern (sofern unterstützt), oder 0, um Dateien herunterzuladen. Dadurch wird der macOS-File-Provider-Modus nicht aktiviert.

Speichern Sie zum Beispiel ein Konto und melden Sie sich anschließend in der Desktop-App an:

nextcloudcmd --userid carla --serverurl https://cloud.example.com --localdirpath "$HOME/Nextcloud"
