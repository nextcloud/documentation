Erweiterte Konfiguration

Sie können die Desktop-App über Befehlszeilenoptionen, nextcloud.cfg und Umgebungsvariablen konfigurieren. Verwenden Sie für die dort verfügbaren Optionen das Fenster Einstellungen der App; diese Seite beschreibt erweiterte Einstellungen und Überschreibungen. Informationen zum separaten Werkzeug für einen einzelnen Synchronisierungslauf finden Sie unter Befehlszeilen-Client.

Die unten genannten Standardwerte beziehen sich auf den Standard-Nextcloud-Client. Gebrandete Clients, Server-Fähigkeiten und Betriebssystemrichtlinien können einige Standardwerte ändern. Einstellungen der Synchronisierungs-Engine gelten für die klassische Synchronisierung, einschließlich virtueller Dateien unter Windows. Die macOS-File-Provider-Erweiterung verarbeitet ihre Dateiübertragungen selbst; diese Einstellungen konfigurieren nicht deren Übertragungs-Engine. Siehe Verwendung des macOS-Dateianbieters.

Befehlszeilenoptionen

Starten Sie die Desktop-App mit nextcloud [options]. Mit nextcloud --help sehen Sie die Optionen Ihrer installierten Version. Optionen mit einem Wert akzeptieren sowohl --option value als auch --option=value.

Beenden Sie den laufenden Client, bevor Sie Startoptionen oder Umgebungsvariablen anwenden. Das Starten einer weiteren Instanz kann Befehle an den vorhandenen Prozess weiterleiten, statt einen neuen Prozess mit der gewünschten Umgebung zu starten.

Kontoeinstellungsoptionen

Diese Optionen erstellen und speichern ein Konto und beenden sich dann. Starten Sie die Desktop-App erneut, um das Konto zu verwenden.

Parameter

Standard

Beschreibung

--userid <user>

Erforderlich

Benutzer-ID für das zu erstellende Konto.

--serverurl <url>

Erforderlich

Basis-URL des Nextcloud-Servers, zum Beispiel https://cloud.example.com.

--apppassword <password>

Nicht gesetzt

App-Passwort für das Konto. Wird es weggelassen, wird das Konto gespeichert und Sie müssen sich später in der Desktop-App anmelden.

--localdirpath <path>

Vorgeschlagener Ordner

Lokaler Synchronisierungsordner. Wird er weggelassen, wird der vom Einrichtungsassistenten vorgeschlagene Ordner verwendet. Ein vorhandener Ordner muss leer sein. Wird ignoriert, wenn der macOS-File-Provider-Modus aktiviert ist.

--remotedirpath <path>

/

Entfernter Ordner für die neue klassische Synchronisierungsverbindung. Gilt, wenn ein lokaler Synchronisierungsordner erstellt wird.

--isvfsenabled <0|1>

0

Verwenden Sie 1, um für den neuen klassischen Synchronisierungsordner virtuelle Dateien anzufordern (sofern unterstützt), oder 0, um Dateien herunterzuladen. Dadurch wird der macOS-File-Provider-Modus nicht aktiviert.

Erstellen Sie zum Beispiel ein Konto und melden Sie sich anschließend in der Desktop-App an:

nextcloud --userid carla --serverurl https://cloud.example.com --localdirpath "$HOME/Nextcloud"

Konfigurationsdatei

Der Client speichert seine Einstellungen im INI-Format in nextcloud.cfg. Beenden Sie den Client und sichern Sie diese Datei, bevor Sie sie bearbeiten, und starten Sie den Client anschließend erneut. Änderungen im Fenster Einstellungen der App können die entsprechenden Werte in der Datei überschreiben.

Die Standardstandorte sind:

  • Linux: $HOME/.config/Nextcloud/nextcloud.cfg. Wenn XDG_CONFIG_HOME gesetzt ist, $XDG_CONFIG_HOME/Nextcloud/nextcloud.cfg.

  • Windows: %APPDATA%\Nextcloud\nextcloud.cfg.

  • macOS, Client 33.0.0 und höher: „$HOME/Library/Containers/com.nextcloud.desktopclient/Data/Library/Preferences/Nextcloud/nextcloud.cfg“.

  • Ältere macOS Clients: $HOME/Library/Preferences/Nextcloud/nextcloud.cfg.

--confdir überschreibt das Konfigurationsverzeichnis. Gebrandete Clients können ein anderes Verzeichnis und einen anderen Dateinamen verwenden. Speichern Sie in Citrix- und anderen Umgebungen mit servergespeicherten Profilen die Konfiguration des Benutzers sitzungsübergreifend, damit die Kontoeinrichtung erhalten bleibt.

Die Tabellen geben für jede Einstellung den INI-Abschnitt an. Zum Beispiel:

[Nextcloud]
remotePollInterval=30000

[General]
logDebug=true
logExpire=48

Kontoidentitäten, Zugangsdaten, Zustand der Synchronisierungsordner, Fenstergeometrie, Caches, Migrationsmarkierungen und der Zustand der Aktualisierungsfunktion werden vom Client verwaltet. Verwenden Sie den Einrichtungsassistenten und das Fenster Einstellungen, um diese Werte zu ändern.

Die Rangfolge hängt von der Einstellung ab. Die unten aufgeführten Überschreibungen per Umgebungsvariable gelten nur für die jeweils zugehörigen Einstellungen. Bei skipUpdateCheck und autoUpdateCheck hat ein Wert in [General] Vorrang vor [Nextcloud]. Unter Windows können Administratorrichtlinien diese Aktualisierungseinstellungen sowie die Einstellungen für Ordnergröße und externen Speicher überschreiben. Einzelheiten zu Aktualisierungsrichtlinien finden Sie unter Automatische Updates in Windows-Umgebungen verhindern.

[Nextcloud]-Sektion

Parameter

Standard

Beschreibung

remotePollInterval

30000 ms

Intervall für die Abfrage von Änderungen beim Server. Werte unter 5000 ms werden auf 30000 ms zurückgesetzt. Server-Push kann die Notwendigkeit von Abfragen verringern.

forceSyncInterval

7200000 ms

Eine Synchronisierung planen, nachdem seit der letzten Synchronisierung diese Zeit vergangen ist (2 Stunden). Werte unter remotePollInterval werden auf dieses Intervall angehoben.

fullLocalDiscoveryInterval

3600000 ms

Nach diesem Intervall (1 Stunde) durchsucht die nächste anstehende Synchronisierung das lokale Dateisystem vollständig. Verwenden Sie -1, um regelmäßige vollständige Scans zu deaktivieren. Wird durch OWNCLOUD_FULL_LOCAL_DISCOVERY_INTERVAL überschrieben.

notificationRefreshInterval

60000 ms

Intervall für die Abfrage von Serverbenachrichtigungen. Werte unter 60000 ms werden auf 60000 ms angehoben.

skipUpdateCheck

false

Prüfungen auf Aktualisierungen deaktivieren und die Oberfläche der Aktualisierungsfunktion ausblenden.

autoUpdateCheck

true

Automatische Prüfungen auf Aktualisierungen aktivieren, sofern skipUpdateCheck false ist.

updateCheckInterval

36000000 ms

Intervall für die automatische Prüfung auf Aktualisierungen (Standard: 10 Stunden). Werte unter 300000 ms (5 Minuten) werden auf dieses Minimum angehoben.

[General]-Sektion

Synchronisierung und Übertragungen

Parameter

Standard

Beschreibung

chunkSize

104857600 Bytes

Anfängliche Chunk-Größe für Uploads (100 MiB). Der Client kann sie während des Uploads anpassen. Server-Fähigkeiten können sie ersetzen; OWNCLOUD_CHUNK_SIZE überschreibt den resultierenden Wert.

minChunkSize

5242880 Bytes

Minimale konfigurierte Chunk-Größe für Uploads (5 MiB). Die Synchronisierungs-Engine begrenzt sie anfänglich auf einen Wert zwischen 5 MB und 5 GB. Wird durch OWNCLOUD_MIN_CHUNK_SIZE überschrieben.

maxChunkSize

104857600 Bytes

Maximale konfigurierte Chunk-Größe für Uploads (100 MiB). Ein vom Server vorgegebenes Maximum hat Vorrang. OWNCLOUD_MAX_CHUNK_SIZE überschreibt den resultierenden Wert.

timeout

300 Sekunden

Standard-Zeitüberschreitung bei Netzwerkinaktivität. Aktivität kann den Zeitgeber zurücksetzen, und einzelne Anfragen können andere Zeitüberschreitungen verwenden. Ein von null verschiedener Wert für OWNCLOUD_TIMEOUT überschreibt ihn.

promptDeleteAllFiles

false

Um Bestätigung bitten, wenn alle Dateien als gelöscht erkannt werden oder die Anzahl gelöschter Dateien deleteFilesThreshold überschreitet. Gilt für die klassische Desktop-Synchronisierung; nextcloudcmd zeigt diese Abfrage nicht an.

deleteFilesThreshold

100 Dateien

Anzahl gelöschter Dateien, ab der promptDeleteAllFiles um Bestätigung bittet. Hat nur eine Wirkung, wenn diese Einstellung aktiviert ist.

moveToTrash

false

Auf dem Server gelöschte Dateien in den lokalen Papierkorb verschieben, statt sie endgültig zu löschen, sofern das lokale Dateisystem dies unterstützt.

newBigFolderSizeLimit

500 MB

Größe, ab der ein neuer entfernter Ordner vor dem Herunterladen bestätigt werden muss. Wird verwendet, wenn useNewBigFolderSizeLimit true ist; ein negativer Wert deaktiviert die Begrenzung. Gilt nicht für Ordner mit virtuellen Dateien.

useNewBigFolderSizeLimit

true

Die Bestätigungsgrenze für die Ordnergröße aktivieren.

confirmExternalStorage

true

Vor dem Synchronisieren neu erkannter Ordner auf externen Speichern nachfragen.

notifyExistingFoldersOverLimit

false

Benachrichtigen, wenn ein bereits synchronisierter Ordner über die aktive Ordnergrößengrenze hinauswächst. Erfordert, dass diese Grenze aktiviert und virtuelle Dateien deaktiviert sind.

stopSyncingExistingFoldersOverLimit

Von notifyExistingFoldersOverLimit

Die Synchronisierung solcher Ordner außerdem anhalten, bis Sie sich entscheiden, sie weiter zu synchronisieren. Erfordert, dass notifyExistingFoldersOverLimit und die Ordnergrößengrenze aktiviert sind.

Bei der klassischen Desktop-Synchronisierung wendet der Client zuerst die Chunk-Einstellungen aus der Konfigurationsdatei an, dann die Server-Fähigkeiten und dann die Überschreibungen per Umgebungsvariable. Anschließend passt er Minimum und Maximum so an, dass die anfängliche Chunk-Größe eingeschlossen ist. Der Konfigurationsschlüssel targetChunkUploadDuration wird von der Synchronisierungs-Engine nicht verwendet; verwenden Sie stattdessen OWNCLOUD_TARGET_CHUNK_UPLOAD_DURATION. forceLoginV2 wird vom Client nicht mehr gelesen.

Netzwerkeinstellungen pro Konto

Verwenden Sie nach Möglichkeit die Netzwerkeinstellungen des Kontos in der App. Die folgenden Werte gehören zur bestehenden Kontogruppe innerhalb von [Accounts]. In der INI-Datei erscheinen sie mit dem Präfix der Konto-ID, zum Beispiel 0\networkProxyType=0 für das Konto 0. Verwenden Sie die Konto-ID, die bereits in Ihrer Datei vorhanden ist. 0 wenn abwesend

0: System-Proxy; 1: SOCKS5-Proxy; 2: kein Proxy; 3: HTTP-Proxy. Bei der Kontoeinrichtung oder Migration kann ein anderer Wert gespeichert werden.

networkProxyHostName

Leer

Proxy-Hostname.

networkProxyPort

0

Proxy-Port. Geben Sie beim Konfigurieren eines manuellen Proxys den tatsächlichen Port an.

networkProxyNeedsAuth

false

Ob der Proxy eine Authentifizierung benötigt.

networkProxyUser

Leer

Proxy-Benutzername.

networkUploadLimitSetting

0

Modus der Upload-Begrenzung: 0 für unbegrenzt, 1 für eine manuelle Begrenzung. Negative Werte sind für die Migration älterer Konfigurationen reserviert.

networkDownloadLimitSetting

0

Modus der Download-Begrenzung: 0 für unbegrenzt, 1 für eine manuelle Begrenzung. Negative Werte sind für die Migration älterer Konfigurationen reserviert.

networkUploadLimit

0 KB/s

Manuelle Upload-Begrenzung, wird verwendet, wenn networkUploadLimitSetting den Wert 1 hat.

Umgebungsvariablen

Setzen Sie Umgebungsvariablen, bevor Sie den Client starten. Eine in einem Terminal gesetzte Variable gilt für Prozesse, die aus diesem Terminal gestartet werden; ein bereits laufender Client oder ein vom Desktop aus gestarteter Client übernimmt sie nicht automatisch. Ändern Sie zum Beispiel unter Linux vorübergehend die Zeitüberschreitung bei Netzwerkinaktivität:

OWNCLOUD_TIMEOUT=600 nextcloud

Das historische Präfix OWNCLOUD_ wird vom Nextcloud-Client weiterhin verwendet. Beachten Sie das Werteformat in der jeweiligen Beschreibung: Einige Schalter erfordern 0 oder 1, während andere auf jeden nicht leeren Wert reagieren, einschließlich 0. Default beschreibt das Verhalten, wenn die Variable nicht gesetzt ist.

Übertragungseinstellungen

Die Überschreibungen für Chunk-Größe und parallele Aufträge werden bei der klassischen Desktop-Synchronisierung nach den Konfigurationswerten und Server-Fähigkeiten angewendet. nextcloudcmd liest diese Variablen ebenfalls, beginnt aber mit den Standardwerten seiner Synchronisierungs-Engine statt mit der Chunk-Konfiguration der Desktop-App.

Parameter

Standard

Beschreibung

OWNCLOUD_CHUNK_SIZE

Effektive Blockgröße

Anfängliche Chunk-Größe in Bytes. Die Desktop-Synchronisierung beginnt mit chunkSize oder der vom Server vorgegebenen Größe. nextcloudcmd verwendet standardmäßig 104857600 Bytes (100 MiB).

OWNCLOUD_MIN_CHUNK_SIZE

Effektives Minimum

Minimale Chunk-Größe in Bytes. Die Desktop-Synchronisierung beginnt mit minChunkSize; nextcloudcmd verwendet standardmäßig 5000000 Bytes (5 MB).

OWNCLOUD_MAX_CHUNK_SIZE

Effektives Maximum

Maximale Chunk-Größe in Bytes. Die Desktop-Synchronisierung beginnt mit maxChunkSize oder dem vom Server vorgegebenen Maximum; nextcloudcmd verwendet standardmäßig 5000000000 Bytes (5 GB).

OWNCLOUD_TARGET_CHUNK_UPLOAD_DURATION

60000 ms

Zieldauer für die dynamische Chunk-Größenanpassung (1 Minute). Verwenden Sie 0, um die dynamische Anpassung zu deaktivieren. Der ähnlich benannte Schlüssel in der Konfigurationsdatei hat keine Wirkung.

OWNCLOUD_MAX_PARALLEL

Server/Protokoll-abhängig

Positive Höchstzahl paralleler Synchronisierungsaufträge. Die Desktop-Synchronisierung verwendet den vom Server vorgegebenen Wert, sofern verfügbar; andernfalls 20 für HTTP/2 oder 6 für HTTP/1. nextcloudcmd verwendet standardmäßig 6. Dies ist nicht die Anzahl gleichzeitiger Dateiübertragungen.

OWNCLOUD_TIMEOUT

timeout oder 300 Sekunden

Zeitüberschreitung bei Netzwerkinaktivität. Eine von null verschiedene Ganzzahl überschreibt timeout in der Desktop-App. nextcloudcmd verwendet standardmäßig 300 Sekunden. Null oder ein ungültiger Wert verwendet den normalen Standardwert.

OWNCLOUD_HTTP2_ENABLED

Deaktiviert

Auf 1 setzen, um HTTP/2 für HTTPS-Anfragen zu erlauben. Andere Werte deaktivieren es. Ob es tatsächlich verwendet wird, hängt weiterhin vom Server und von der Netzwerkverbindung ab.

OWNCLOUD_CHUNKING_NG

Serverfähigkeiten

Auf 0 setzen, um das neuere Protokoll für Uploads in Chunks zu deaktivieren, oder auf 1, um es zu erzwingen. Andere Werte verwenden die Server-Fähigkeit. Erzwingen Sie es nur, wenn der Server es unterstützt.

NEXTCLOUD_BULK_UPLOAD

Serverfähigkeiten

Auf 0 setzen, um Massen-Uploads zu deaktivieren, oder auf 1, um sie zu erzwingen. Andere Werte verwenden die Server-Fähigkeit. Erzwingen Sie sie nur, wenn der Server sie unterstützt.

OWNCLOUD_PARALLEL_CHUNK

Serverabhängig

Nur für den veralteten Upload-Pfad mit Chunks: 0 oder false deaktiviert parallele Chunks. Andere nicht leere Werte aktivieren sie, sofern der Server sie nicht deaktiviert.

OWNCLOUD_LAZYOPS

Deaktiviert

Eine von null verschiedene Ganzzahl fügt Upload-Anfragen den Header OC-LazyOps: true hinzu. Die Wirkung hängt von der Unterstützung durch den Server ab.

Halten Sie die Chunk-Größen positiv. Der Client passt Minimum und Maximum so an, dass die anfängliche Chunk-Größe eingeschlossen ist. Der Parser für Umgebungsvariablen akzeptiert für die drei Chunk-Größen-Überschreibungen vorzeichenlose 32-Bit-Bytewerte; verwenden Sie für diese Variablen daher keine Werte über 4294967295 Bytes.

Synchronisierung und Speicherplatz

Parameter

Standard

Beschreibung

OWNCLOUD_FULL_LOCAL_DISCOVERY_INTERVAL

fullLocalDiscoveryInterval

Nur klassische Desktop-Synchronisierung. Das Intervall für den vollständigen lokalen Scan in Millisekunden überschreiben. Verwenden Sie -1, um regelmäßige vollständige Scans zu deaktivieren.

OWNCLOUD_CRITICAL_FREE_SPACE_BYTES

512000000 Bytes

Die Ordnersynchronisierung abbrechen, wenn der verbleibende lokale Speicherplatz unter diesem Schwellenwert liegt (512 MB). Der Wert liegt zwischen null und OWNCLOUD_FREE_SPACE_BYTES.

OWNCLOUD_FREE_SPACE_BYTES

1000000000 Bytes

Downloads überspringen oder abbrechen, die weniger als diese Menge an freiem lokalem Speicherplatz übrig lassen würden (1 GB). Andere Synchronisierungsvorgänge können fortgesetzt werden.

OWNCLOUD_BLACKLIST_TIME_MIN

25 Sekunden

Minimale Wartezeit bis zum erneuten Versuch bei Dateien, deren Synchronisierung fehlgeschlagen ist. Werte unter 25 werden auf 25 angehoben.

OWNCLOUD_BLACKLIST_TIME_MAX

86400 Sekunden

Maximale Wartezeit bis zum erneuten Versuch bei Dateien, deren Synchronisierung fehlgeschlagen ist (1 Tag). Nur positive Werte überschreiben den Standardwert.

OWNCLOUD_UPLOAD_CONFLICT_FILES

Serverfähigkeiten

Auf 1 setzen, um Konfliktkopien hochzuladen, oder auf 0, um deren Upload zu verhindern. Ein nicht leerer Wert überschreibt die Servereinstellung. Siehe Konflikte.

Downloads, die wegen des Schwellenwerts für freien Speicherplatz übersprungen wurden, werden in späteren Synchronisierungsläufen erneut versucht. Der kritische Schwellenwert stoppt die gesamte Ordnersynchronisierung. Diese Grenzen sind unabhängig von Ihrem Speicherkontingent auf dem Server.

Parameter

Standard

Beschreibung

OWNCLOUD_CONTENT_CHECKSUM_TYPE

Serverpräferenz, dann SHA1

Den bevorzugten Prüfsummenalgorithmus für Uploads überschreiben. Wählen Sie einen Algorithmus, der sowohl vom Client als auch vom Server unterstützt wird.

OWNCLOUD_DISABLE_CHECKSUM_UPLOAD

Nicht gesetzt

Jeder nicht leere Wert deaktiviert das Senden von Upload-Prüfsummen. Entfernen Sie die Variable, um das normale Hochladen von Prüfsummen wiederherzustellen.

OWNCLOUD_DISABLE_CHECKSUM_COMPUTATIONS

Nicht gesetzt

Jeder nicht leere Wert deaktiviert synchrone Prüfsummenberechnungen. Upload- und Download-Pfade mit asynchronen Berechnungen laufen weiterhin.

Verwenden Sie Prüfsummen-Überschreibungen nur zur Diagnose eines bestimmten Kompatibilitätsproblems; das Deaktivieren von Prüfsummen verringert die während der Synchronisierung verwendeten Integritätsprüfungen.
