Avanceret opsætning

Du kan sætte skrivebordsappen op via parametre på kommandolinjen, nextcloud.cfg og miljøvariabler. Brug appens vindue Indstillinger til de indstillinger, der findes dér; denne side beskriver avancerede indstillinger og tilsidesættelser. Se Kommandolinje-klient for det separate værktøj, der kører en enkelt synkronisering.

Standardværdierne nedenfor gælder den almindelige Nextcloud-klient. Klienter med eget brand, serverens understøttelse og styresystemets politikker kan ændre nogle standarder. Indstillingerne for synkroniseringsmotoren gælder klassisk synkronisering, også virtuelle filer på Windows. File Provider-udvidelsen på macOS håndterer selv sine filoverførsler; disse indstillinger styrer ikke dens overførsler. Se Brug af File Provider på macOS.

Parametre på kommandolinjen

Start skrivebordsappen med nextcloud [options]. Brug nextcloud --help for at se parametrene i din installerede version. Parametre med en værdi accepterer både --option value og --option=value.

Afslut den kørende klient, før du anvender parametre ved start eller miljøvariabler. Hvis du starter en instans mere, kan kommandoerne blive sendt videre til den eksisterende proces i stedet for at starte en ny proces med de ønskede miljøvariabler.

Parametre for logning

Parameter

Standard

Beskrivelse

--logwindow, -l

Ikke sat

Åbn vinduet med logoutput.

--logfile <filename>

Ikke sat

Skriv logfiler til denne fil. Brug - for at skrive til standard output. Har forrang for --logdir.

--logdir <directory>

Værdien af logDir

Skriv roterende logfiler til denne mappe.

--logexpire <hours>

Værdien af logExpire

Angiv opbevaringstid for roterende logfiler. En positiv værdi tilsidesætter logExpire; nul eller en negativ værdi bruger indstillingen i konfigurationen.

--logflush

Værdien af logFlush

Skriv logbufferen til disken efter hver logpost, så de seneste beskeder er tilgængelige med det samme.

--logdebug

Værdien af logDebug

Slå fejlsøgningsbeskeder til i Nextclouds logkategorier. Det slår ikke alle Qt’s fejlsøgningskategorier til.

--debug

Ikke sat

Slå også fejlsøgningslogning til. Brug hellere --logdebug, når du indsamler logfiler til fejlfinding.

Saml f.eks. fejlsøgningsoutput i en fil på Linux:

nextcloud --logdebug --logflush --logfile "$HOME/nextcloud-debug.log"

Se Sektionen [General] for permanente indstillinger for logning.

Parametre for kontoopsætning

Disse parametre opretter og gemmer en konto og lukker derefter. Start skrivebordsappen igen for at bruge kontoen.

Parameter

Standard

Beskrivelse

--userid <user>

Påkrævet

Bruger-ID for den konto, der skal oprettes.

--serverurl <url>

Påkrævet

Nextcloud-serverens basis-URL, f.eks. https://cloud.example.com.

--apppassword <password>

Ikke sat

App-adgangskode til kontoen. Hvis den udelades, gemmes kontoen, og du skal logge ind fra skrivebordsappen senere.

--localdirpath <path>

Foreslået mappe

Lokal synkroniseringsmappe. Hvis den udelades, bruges den mappe, opsætningsguiden foreslår. En eksisterende mappe skal være tom. Ignoreres, når File Provider-tilstand på macOS er slået til.

--remotedirpath <path>

/

Mappe på serveren til den nye klassiske synkroniseringsforbindelse. Gælder, når der oprettes en lokal synkroniseringsmappe.

--isvfsenabled <0|1>

0

Brug 1 for at bede om virtuelle filer for den nye klassiske synkroniseringsmappe, hvor det understøttes, eller 0 for at hente filerne. Det slår ikke File Provider-tilstanden på macOS til.

Opret f.eks. en konto, og log ind fra skrivebordsappen bagefter:

nextcloud --userid carla --serverurl https://cloud.example.com --localdirpath "$HOME/Nextcloud"

Konfigurationsfil

Klienten gemmer sine indstillinger i nextcloud.cfg i INI-format. Afslut klienten, og tag en sikkerhedskopi af filen, før du redigerer den, og start derefter klienten igen. Ændringer i appens vindue Indstillinger kan overskrive de tilsvarende værdier i filen.

Standardplaceringerne er:

  • Linux: $HOME/.config/Nextcloud/nextcloud.cfg. Hvis XDG_CONFIG_HOME er sat, så brug $XDG_CONFIG_HOME/Nextcloud/nextcloud.cfg.

  • Windows: %APPDATA%\Nextcloud\nextcloud.cfg.

  • macOS, klient 33.0.0 og nyere: $HOME/Library/Containers/com.nextcloud.desktopclient/Data/Library/Preferences/Nextcloud/nextcloud.cfg.

  • Ældre macOS-klienter: $HOME/Library/Preferences/Nextcloud/nextcloud.cfg.

--confdir tilsidesætter konfigurationsmappen. Klienter med eget brand kan bruge en anden mappe og et andet filnavn. I Citrix og andre miljøer med roamingprofiler skal brugerens konfiguration gemmes mellem sessioner, så kontoopsætningen ikke går tabt.

Tabellerne angiver INI-sektionen for hver indstilling. For eksempel:

[Nextcloud]
remotePollInterval=30000

[General]
logDebug=true
logExpire=48

Kontoidentiteter, loginoplysninger, synkroniseringsmappernes tilstand, vinduesgeometri, cache, migreringsmarkører og opdateringsstatus administreres af klienten. Brug opsætningsguiden og vinduet Indstillinger til at ændre de værdier.

Hvilken værdi der har forrang, afhænger af indstillingen. Tilsidesættelserne via miljøvariabler nedenfor gælder kun de tilsvarende indstillinger. For skipUpdateCheck og autoUpdateCheck har en værdi i [General] forrang for [Nextcloud]. På Windows kan administratorpolitikker tilsidesætte disse indstillinger for opdatering og indstillingerne for mappestørrelse og eksterne lagre. Se Slå automatisk opdatering fra i Windows for at få oplysninger om politikker for opdatering.

Sektionen [Nextcloud]

Parameter

Standard

Beskrivelse

remotePollInterval

30000 ms

Interval for at spørge serveren om ændringer. Værdier under 5000 ms bliver til 30000 ms. Push fra serveren kan mindske behovet for at spørge.

forceSyncInterval

7200000 ms

Planlæg en synkronisering, når der er gået så lang tid siden den sidste synkronisering (2 timer). Værdier under remotePollInterval hæves til det interval.

fullLocalDiscoveryInterval

3600000 ms

Efter dette interval (1 time) scanner den næste mulige synkronisering hele det lokale filsystem. Brug -1 for at slå de periodiske fulde scanninger fra. Tilsidesættes af OWNCLOUD_FULL_LOCAL_DISCOVERY_INTERVAL.

notificationRefreshInterval

60000 ms

Interval for at hente notifikationer fra serveren. Værdier under 60000 ms hæves til 60000 ms.

skipUpdateCheck

false

Slå søgning efter opdateringer fra, og skjul brugerfladen til opdatering.

autoUpdateCheck

true

Slå automatisk søgning efter opdateringer til, forudsat at skipUpdateCheck er false.

updateCheckInterval

36000000 ms

Interval for automatisk søgning efter opdateringer (standard: 10 timer). Værdier under 300000 ms (5 minutter) hæves til det minimum.

Sektionen [General]

Synkronisering og overførsler

Parameter

Standard

Beskrivelse

chunkSize

104857600 byte

Første chunk-størrelse ved overførsel (100 MiB). Klienten kan justere den under overførslen. Serverens understøttelse kan erstatte den; OWNCLOUD_CHUNK_SIZE tilsidesætter den resulterende værdi.

minChunkSize

5242880 byte

Mindste indstillede chunk-størrelse ved overførsel (5 MiB). Synkroniseringsmotoren begrænser den først til mellem 5 MB og 5 GB. Tilsidesættes af OWNCLOUD_MIN_CHUNK_SIZE.

maxChunkSize

104857600 byte

Største indstillede chunk-størrelse ved overførsel (100 MiB). Et maksimum fra serveren har forrang. OWNCLOUD_MAX_CHUNK_SIZE tilsidesætter den resulterende værdi.

timeout

300 sekunder

Standardtimeout ved inaktivitet på netværket. Aktivitet kan nulstille uret, og enkelte forespørgsler kan bruge andre timeouts. En OWNCLOUD_TIMEOUT forskellig fra nul tilsidesætter den.

promptDeleteAllFiles

false

Bed om bekræftelse, når alle filer registreres som slettet, eller når antallet af slettede filer overstiger deleteFilesThreshold. Gælder klassisk synkronisering i skrivebordsappen; nextcloudcmd stiller ikke dette spørgsmål.

deleteFilesThreshold

100 filer

Når antallet af sletninger overstiger dette tal, beder promptDeleteAllFiles om bekræftelse. Har ingen virkning, medmindre den indstilling er slået til.

moveToTrash

false

Flyt filer, der er slettet på serveren, til den lokale papirkurv i stedet for at slette dem permanent, hvor det lokale filsystem understøtter det.

newBigFolderSizeLimit

500 MB

Nye mapper på serveren, der er større end dette, skal bekræftes, før de hentes. Bruges, når useNewBigFolderSizeLimit er true; en negativ værdi slår grænsen fra. Gælder ikke mapper med virtuelle filer.

useNewBigFolderSizeLimit

true

Slå grænsen for bekræftelse af mappestørrelse til.

confirmExternalStorage

true

Spørg, før nyfundne mapper på eksterne lagre synkroniseres.

notifyExistingFoldersOverLimit

false

Giv besked, når en eksisterende synkroniseret mappe vokser ud over den aktive grænse for mappestørrelse. Kræver, at grænsen er slået til, og at virtuelle filer er slået fra.

stopSyncingExistingFoldersOverLimit

Værdien af notifyExistingFoldersOverLimit

Stop også synkroniseringen af sådanne mapper, indtil du vælger at fortsætte. Kræver, at notifyExistingFoldersOverLimit og grænsen for mappestørrelse er slået til.

Ved klassisk synkronisering i skrivebordsappen anvender klienten chunk-indstillingerne fra konfigurationsfilen, derefter serverens muligheder og til sidst tilsidesættelser via miljøvariabler. Bagefter justerer den minimum og maksimum, så de omfatter den første chunk-størrelse. Konfigurationsnøglen targetChunkUploadDuration bruges ikke af synkroniseringsmotoren; brug OWNCLOUD_TARGET_CHUNK_UPLOAD_DURATION i stedet. forceLoginV2 læses ikke længere af klienten.

Netværksindstillinger for hver konto

Brug så vidt muligt kontoens netværksindstillinger i appen. Værdierne nedenfor hører til den eksisterende kontogruppe i [Accounts]. I INI-filen står de med kontoens ID foran, f.eks. 0\networkProxyType=0 for konto 0. Brug det konto-ID, der allerede står i din fil. Adgangskoder til proxyen hører hjemme i systemets nøglering.

Parameter

Standard

Beskrivelse

networkProxyType

0, hvis den mangler

0: systemets proxy; 1: SOCKS5-proxy; 2: ingen proxy; 3: HTTP-proxy. Kontoopsætning eller migrering kan gemme en anden værdi.

networkProxyHostName

Tom

Proxyens værtsnavn.

networkProxyPort

0

Proxyens port. Angiv den faktiske port, når du sætter en manuel proxy op.

networkProxyNeedsAuth

false

Om proxyen kræver godkendelse.

networkProxyUser

Tom

Brugernavn til proxyen.

networkUploadLimitSetting

0

Tilstand for grænse ved overførsel: 0 for ubegrænset, 1 for en manuel grænse. Negative værdier er forbeholdt migrering fra ældre versioner.

networkDownloadLimitSetting

0

Tilstand for grænse ved hentning: 0 for ubegrænset, 1 for en manuel grænse. Negative værdier er forbeholdt migrering fra ældre versioner.

networkUploadLimit

0 KB/s

Manuel grænse ved overførsel, som bruges, når networkUploadLimitSetting er 1.

networkDownloadLimit

0 KB/s

Manuel grænse ved hentning, som bruges, når networkDownloadLimitSetting er 1.

Sektionen [Proxy] på øverste niveau bevares til migrering fra ældre klienter. Nuværende konti i skrivebordsappen bruger indstillingerne for hver konto ovenfor. De ældre proxyindstillinger kan fjernes automatisk efter migreringen.

Parameter

Standard

Beskrivelse

type

0

Ældre proxytype: 0 for systemets proxy, 1 for SOCKS5, 2 for ingen proxy eller 3 for HTTP-proxy.

host

Tom

Værtsnavn for den ældre proxy.

port

0

Port for den ældre proxy.

needsAuth

false

Om den ældre proxy kræver godkendelse.

user

Tom

Brugernavn til den ældre proxy.

Miljøvariabler

Sæt miljøvariabler, før du starter klienten. En variabel, der er sat i en terminal, gælder for processer, der startes fra den terminal; en klient, der allerede kører eller er startet fra skrivebordet, arver den ikke automatisk. Skift f.eks. midlertidigt timeout ved inaktivitet på netværket på Linux:

OWNCLOUD_TIMEOUT=600 nextcloud

Det historiske præfiks OWNCLOUD_ bruges stadig af Nextcloud-klienten. Følg værdiformatet i hver beskrivelse: Nogle til/fra-variabler kræver 0 eller 1, mens andre reagerer på enhver værdi, der ikke er tom, også 0. Kolonnen Standard beskriver adfærden, når variablen ikke er sat.

Indstillinger for overførsel

Tilsidesættelserne for chunk-størrelse og parallelle job anvendes efter konfigurationsværdierne og serverens muligheder ved klassisk synkronisering i skrivebordsappen. nextcloudcmd læser også disse variabler, men starter med synkroniseringsmotorens standarder i stedet for skrivebordsappens chunk-indstillinger.

Parameter

Standard

Beskrivelse

OWNCLOUD_CHUNK_SIZE

Den faktiske chunk-størrelse

Første chunk-størrelse i byte. Synkronisering i skrivebordsappen starter fra chunkSize eller størrelsen fra serveren. nextcloudcmd bruger som standard 104857600 byte (100 MiB).

OWNCLOUD_MIN_CHUNK_SIZE

Det faktiske minimum

Mindste chunk-størrelse i byte. Synkronisering i skrivebordsappen starter fra minChunkSize; nextcloudcmd bruger som standard 5000000 byte (5 MB).

OWNCLOUD_MAX_CHUNK_SIZE

Det faktiske maksimum

Største chunk-størrelse i byte. Synkronisering i skrivebordsappen starter fra maxChunkSize eller maksimummet fra serveren; nextcloudcmd bruger som standard 5000000000 byte (5 GB).

OWNCLOUD_TARGET_CHUNK_UPLOAD_DURATION

60000 ms

Måltid for dynamisk chunk-størrelse (1 minut). Brug 0 for at slå dynamisk størrelse fra. Konfigurationsnøglen med det lignende navn har ingen virkning.

OWNCLOUD_MAX_PARALLEL

Afhænger af server/protokol

Positivt maksimalt antal parallelle synkroniseringsjob. Synkronisering i skrivebordsappen bruger værdien fra serveren, når den findes; ellers bruges 20 for HTTP/2 eller 6 for HTTP/1. nextcloudcmd bruger som standard 6. Det er ikke antallet af samtidige filoverførsler.

OWNCLOUD_TIMEOUT

timeout eller 300 sekunder

Timeout ved inaktivitet på netværket. Et heltal forskelligt fra nul tilsidesætter timeout i skrivebordsappen. nextcloudcmd bruger som standard 300 sekunder. Nul eller en ugyldig værdi bruger den normale standard.

OWNCLOUD_HTTP2_ENABLED

Slået fra

Sæt til 1 for at tillade HTTP/2 for HTTPS-forespørgsler. Andre værdier slår det fra. Om det faktisk bruges, afhænger stadig af serveren og netværksforbindelsen.

OWNCLOUD_CHUNKING_NG

Som serveren understøtter

Sæt til 0 for at slå den nyere protokol til overførsel i chunks fra eller 1 for at gennemtvinge den. Andre værdier bruger serverens mulighed. Gennemtving den kun, når serveren understøtter den.

NEXTCLOUD_BULK_UPLOAD

Som serveren understøtter

Sæt til 0 for at slå masseoverførsler fra eller 1 for at gennemtvinge dem. Andre værdier bruger serverens mulighed. Gennemtving dem kun, når serveren understøtter dem.

OWNCLOUD_PARALLEL_CHUNK

Afhænger af serveren

Kun for den ældre metode til overførsel i chunks: 0 eller false slår parallelle chunks fra. Andre værdier, der ikke er tomme, slår dem til, medmindre serveren slår dem fra.

OWNCLOUD_LAZYOPS

Slået fra

Et heltal forskelligt fra nul tilføjer headeren OC-LazyOps: true til forespørgsler om overførsel. Virkningen afhænger af serverens understøttelse.

Hold chunk-størrelserne positive. Klienten justerer minimum og maksimum, så de omfatter den første chunk-størrelse. Fortolkningen af miljøvariabler accepterer 32-bit-værdier uden fortegn i byte for de tre tilsidesættelser af chunk-størrelse, så brug ikke værdier over 4294967295 byte for de variabler.

Synkronisering og diskplads

Parameter

Standard

Beskrivelse

OWNCLOUD_FULL_LOCAL_DISCOVERY_INTERVAL

fullLocalDiscoveryInterval

Kun klassisk synkronisering i skrivebordsappen. Tilsidesæt intervallet for fuld lokal scanning i millisekunder. Brug -1 for at slå de periodiske fulde scanninger fra.

OWNCLOUD_CRITICAL_FREE_SPACE_BYTES

512000000 byte

Afbryd synkroniseringen af mappen, når den resterende lokale plads er under denne grænse (512 MB). Værdien begrænses til mellem nul og OWNCLOUD_FREE_SPACE_BYTES.

OWNCLOUD_FREE_SPACE_BYTES

1000000000 byte

Spring over eller afbryd hentninger, der ville efterlade mindre end denne mængde ledig lokal plads (1 GB). Anden synkronisering kan fortsætte.

OWNCLOUD_BLACKLIST_TIME_MIN

25 sekunder

Mindste ventetid, før der prøves igen for filer, der ikke kunne synkroniseres. Værdier under 25 hæves til 25.

OWNCLOUD_BLACKLIST_TIME_MAX

86400 sekunder

Største ventetid, før der prøves igen for filer, der ikke kunne synkroniseres (1 dag). Kun positive værdier tilsidesætter standarden.

OWNCLOUD_UPLOAD_CONFLICT_FILES

Som serveren understøtter

Sæt til 1 for at overføre konfliktkopier eller 0 for at forhindre, at de overføres. En værdi, der ikke er tom, tilsidesætter serverens indstilling. Se Konflikter.

Hentninger, der springes over på grund af grænsen for ledig plads, prøves igen i senere synkroniseringer. Den kritiske grænse stopper hele mappens synkronisering. Grænserne er uafhængige af din lagerkvote på serveren.

Kontrolsummer

Parameter

Standard

Beskrivelse

OWNCLOUD_CONTENT_CHECKSUM_TYPE

Serverens præference, derefter SHA1

Tilsidesæt den foretrukne algoritme til kontrolsummer ved overførsel. Vælg en algoritme, som både klient og server understøtter.

OWNCLOUD_DISABLE_CHECKSUM_UPLOAD

Ikke sat

Enhver værdi, der ikke er tom, slår afsendelse af kontrolsummer ved overførsel fra. Fjern variablen for at gendanne normal afsendelse af kontrolsummer.

OWNCLOUD_DISABLE_CHECKSUM_COMPUTATIONS

Ikke sat

Enhver værdi, der ikke er tom, slår synkron beregning af kontrolsummer fra. Overførsel og hentning, der bruger asynkron beregning, kører stadig.

Brug kun tilsidesættelser af kontrolsummer, når du fejlsøger et bestemt kompatibilitetsproblem; når kontrolsummer slås fra, mindskes de integritetskontroller, der bruges under synkroniseringen.

Fejlfinding

Parameter

Standard

Beskrivelse

OWNCLOUD_SQLITE_JOURNAL_MODE

WAL eller DELETE

Tilsidesæt tilstanden for synkroniseringsjournalens database. Normalt WAL; DELETE på FAT-filsystemer på Windows og synkroniseringsstier på macOS under /Volumes/. Ændr det kun, når du fejlsøger et kompatibilitetsproblem med databasen.

OWNCLOUD_SQLITE_LOCKING_MODE

EXCLUSIVE

Tilsidesæt SQLites låsetilstand for synkroniseringsjournalens database.

OWNCLOUD_SQLITE_TEMP_STORE

SQLites standard

Tilsidesæt SQLite-indstillingen temp_store for synkroniseringsjournalens database.

OWNCLOUD_CORE_DUMP

Ikke sat

På Unix-systemer får enhver værdi, der ikke er tom, skrivebordsappen til at bede om ubegrænset størrelse på core dumps. Styresystemets begrænsninger gælder stadig.

QT_LOGGING_RULES

Qt’s standarder for logning

Angiv filtre for logkategorier, f.eks. nextcloud.*.debug=true. Med denne Qt-variabel kan du også vælge enkelte kategorier.

Se Håndtering af loginoplysninger for loginoplysninger til nextcloudcmd. Dens variabler NC_USER og NC_PASSWORD sætter ikke konti op i skrivebordsappen.
