已刪除的檔案

當你在 Nextcloud 刪除檔案或資料夾時，該項目通常會移至資源回收筒，而不會立即刪除，讓你日後可以還原。

當發生以下任何一種情況時，資源回收筒內的項目將被永久刪除：

  • 你手動選擇 永久刪除。

  • 「已刪除的檔案」應用程式根據設定的保留政策移除項目。

  • 資源回收筒的實際容量上限已超出，而項目符合移除條件，需要騰出空間。

在 Nextcloud 網頁介面的「檔案」區域選擇 已刪除的檔案，即可尋找已刪除的檔案。你可以在該處還原項目、下載至裝置，或永久刪除。

還原項目時，Nextcloud 通常會嘗試將其放回原來的位置。如果原來的位置已不存在或無法寫入，項目會還原至「檔案」區域的根目錄。如果已有同名項目，Nextcloud 會為還原的項目指定一個獨一無二的名稱。

Note

如果已啟用「版本」應用程式，已刪除檔案的相關版本也會移至資源回收筒，並在還原檔案時一併還原。

配額

資源回收筒內的檔案及資料夾不會計入你的正常儲存空間配額。

如需了解儲存空間配額的計算方式，請參閱 存儲配額。

刪除共享檔案時會發生什麼事情

刪除共用檔案後的處理方式，取決於刪除者及項目擁有者的身分。

例如，用戶 User1 與 User2 及 User3 共用名為 TheProject/ 的資料夾：

  1. User2（共用項目的接收者）刪除 TheProject/ 內名為 Phase2 的資料夾或檔案。

    TheProject/Phase2 會移至擁有者 User1 的資源回收筒；如情況允許，User2 的資源回收筒亦會存放一份副本。該項目會從 User3 的共用資料夾中移除，但 User3 的資源回收筒不會收到副本。

  2. 擁有者 User1 刪除 TheProject/Phase2。

    該項目會移至 User1 的資源回收筒，並從 User2 及 User3 的共用資料夾中移除，不會放入他們的資源回收筒。

實際處理方式可能因共用類型及授予的權限而異。視乎權限，其他用戶可能可以複製、重新命名、移動或再次共用檔案。這些操作可能影響產生的檔案由哪個帳戶擁有，以及刪除後會進入哪個資源回收筒。

Note

當共用項目的接收者刪除其他用戶擁有的項目時，Nextcloud 會將該項目移至擁有者的資源回收筒。系統通常亦會在刪除者的資源回收筒建立副本，但只會盡力處理，並不保證成功。

「已刪除的檔案」應用程式如何管理儲存空間

「已刪除的檔案」應用程式透過兩項相關規則管理資源回收筒的內容：

  • 儲存空間上限決定資源回收筒可以使用多少空間。

  • 保留政策決定已刪除的項目何時符合永久刪除條件。

資源回收筒的儲存空間上限

對設有儲存空間配額的帳戶，資源回收筒的默認上限為帳戶剩餘配額空間的最多 50%。計算時會先扣除帳戶現有檔案佔用的空間，因此並非總配額的 50%。

例如，如果你的配額為 10 GB，而現有檔案佔用 8 GB，資源回收筒的默認可用空間便會根據剩餘的 2 GB 計算。

對沒有儲存空間配額的帳戶，默認上限會改為根據檔案系統的可用空間計算。管理員可以設定全域或個別帳戶的資源回收筒容量，以覆蓋上述默認值。

當資源回收筒超出實際容量上限時，Nextcloud 會從最舊的項目開始移除符合刪除條件的項目，直至使用量重新降至上限以內。

保留期限與永久刪除

默認情況下，已刪除的檔案會保留至少 30 天。之後，如有需要騰出空間，符合條件的項目可能會被永久刪除；它們不一定會在 30 天後立即刪除。

管理員可以設定不同的最短及最長保留期限。視乎設定，即使目前不需要騰出儲存空間，超過最長保留期限的項目仍可能被永久刪除。亦可以停用自動到期刪除功能。

對設有最短保留期限的政策，項目必須在該期限屆滿後，才符合因空間不足而清理的條件。沒有設定最短保留期限的政策，則可能容許不論項目已刪除多久，都因空間需要而清理。超過已設定最長保留期限的項目，無論是否需要騰出空間，都可以被永久刪除。

相關設定為 trashbin_retention_obligation。如需了解可用的設定值，以及它們與配額和資源回收筒容量的相互影響，請參閱 管理員手冊的「已刪除的檔案」章節。

Note

當資源回收筒超出實際容量上限，而且項目已達到最短保留期限時，「已刪除的檔案」應用程式可能會在最長保留期限屆滿前永久刪除該項目。
