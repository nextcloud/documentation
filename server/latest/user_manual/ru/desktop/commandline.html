Клиент командной строки

nextcloudcmd синхронизирует локальную папку с сервером Nextcloud и завершает работу. При необходимости он может выполнять последующие синхронизации, но, в отличие от приложения для ПК, не отслеживает постоянно локальные файлы и не опрашивает сервер на предмет изменений. Параметры, передаваемые команде nextcloud приложения для ПК, описаны в разделе Параметры командной строки.

Установка

Установите пакет, предоставляющий nextcloudcmd. Доступность зависит от операционной системы и пакета:

Операционная система

Источник пакетов

Alpine Linux

nextcloud-client

Debian

nextcloud-desktop-cmd

Fedora

nextcloud-client

Ubuntu

nextcloud-desktop-cmd

PPA Ubuntu

Nextcloud client PPA

Windows

Nextcloud downloads

Использование

Укажите существующую локальную папку и базовый URL сервера Nextcloud:

nextcloudcmd [options] local_directory server_url

Например, синхронизируйте удалённую папку Music с существующей локальной папкой:

nextcloudcmd --user carla --path /Music "$HOME/media/music" https://cloud.example.com

Клиент запрашивает пароль. Можно использовать пароль приложения из параметров безопасности учётной записи Nextcloud. Не добавляйте конечную точку WebDAV к URL сервера; для удалённой вложенной папки используйте --path.

Чтобы показать справку, запустите nextcloudcmd без аргументов; чтобы показать версию — nextcloudcmd --version. Параметры со значениями принимают как --option value, так и --option=value.

Параметры

Параметр

По умолчанию

Описание

--path <path>

Корень сервера

Синхронизировать вложенную папку на сервере, например /Documents.

--user <user>, -u <user>

См. учётные данные ниже

Имя для входа. Переопределяет имя пользователя в URL сервера.

--password <password>, -p <password>

См. учётные данные ниже

Пароль или пароль приложения. Переопределяет пароль в URL сервера. Пароли, указанные в командной строке, могут быть видны в списках процессов и истории командной оболочки.

-n

Не задано

Читать учётные данные из подходящей записи узла или записи по умолчанию в .netrc. Они заменяют учётные данные, указанные в URL или с помощью --user и --password.

--non-interactive

Не задано

Не запрашивать учётные данные. Отсутствующие учётные данные читать из NC_USER и NC_PASSWORD.

--silent, -s

Не задано

Подавлять сообщения журнала Qt. Подавляет не все сообщения консоли.

--trust

Не задано

Принимать недоверенные сертификаты TLS. Использовать только для контролируемой диагностики; обычно следует исправить параметры доверия к сертификатам.

--httpproxy <url>

Прокси не задан явно

Задать HTTP-прокси в виде http://hostname:port. Этот параметр не разбирает учётные данные прокси в URL.

--exclude <file>

Системный список исключений

Добавить список исключений. Файл должен существовать. Привязка шаблонов зависит от имени файла; см. Списки исключений.

--exclude-anchored <file>

Не задано

Добавить список исключений с шаблонами, привязанными к корню синхронизации, независимо от имени файла.

--unsyncedfolders <file>

Не задано

Читать удалённые папки, исключаемые из синхронизации, по одному относительному пути в строке. Пустые строки и строки, начинающиеся с #, игнорируются.

--max-sync-retries <number>

3

Максимальное число повторных запусков, когда механизм синхронизации запрашивает ещё одну синхронизацию. Это не общее число повторов для каждого неудачного запроса.

--uplimit <number>

0 КБ/с

Ограничение скорости загрузки в КБ/с (1000 байт в секунду). Ноль означает отсутствие ограничений.

--downlimit <number>

0 КБ/с

Ограничение скорости скачивания в КБ/с (1000 байт в секунду). Ноль означает отсутствие ограничений.

-h

Скрытые файлы включены

Включить скрытые файлы. Это уже поведение по умолчанию; -h не показывает справку.

--logdebug

Не задано

Включить отладочное журналирование Nextcloud и направлять вывод журнала в стандартный вывод.

--confdir <directory>

Стандартное расположение

Использовать другой каталог конфигурации. Не означает, что однократная синхронизация унаследует все настройки синхронизации клиента для ПК.

--version, -v

Не запрашивается

Показать сведения о версии и завершить работу. Указывайте этот параметр без аргументов каталога и сервера.

Обработка учётных данных

Учётные данные считываются в следующем порядке:

  1. Имя пользователя и пароль в URL сервера, если они указаны.

  2. --user и --password, которые заменяют соответствующие значения в URL.

  3. Соответствующая запись узла или запись по умолчанию в .netrc при использовании -n, которая заменяет оба значения.

  4. Запрашивает отсутствующие значения либо использует переменные среды, приведённые ниже, если указан --non-interactive.

Предпочтительнее вводить пароль по запросу или использовать защищённый файл .netrc, чем указывать пароли в команде или URL.

Параметр

По умолчанию

Описание

NC_USER

Не задано

Резервное имя пользователя для однократной синхронизации с --non-interactive. Используется, только если имя пользователя не задано предыдущими способами.

NC_PASSWORD

Не задано

Резервный пароль для однократной синхронизации с --non-interactive. Используется, только если пароль не задан предыдущими способами.

Эти переменные не предоставляют учётные данные для режима настройки учётной записи, описанного ниже. О переопределениях передачи, общих с механизмом синхронизации клиента для ПК, см. Переменные среды. nextcloudcmd использует начальный размер блока 100 MiB, минимум 5 MB, максимум 5 GB и 6 параллельных заданий, если эти переменные не переопределяют их. Параметры размера блока приложения для ПК из nextcloud.cfg не читаются.

Списки исключений

Клиент загружает системный список исключений, если он доступен. Собственный список можно добавить с помощью --exclude или --exclude-anchored. Отсутствие явно указанного файла считается ошибкой.

При использовании --exclude файл с именем sync-exclude.lst сопоставляет шаблоны относительно корня синхронизации. Для других имён файлов за основу может приниматься папка файла исключений. Используйте --exclude-anchored, если имя файла и его расположение не должны влиять на сопоставление.

Записывайте по одному шаблону в строке. Поддерживаются подстановочные знаки, например:

*.tmp
._*
Thumbs.db

Настройка учётной записи

nextcloudcmd также может сохранить учётную запись для использования приложением для ПК. Этот режим выбирается указанием --userid; позиционные аргументы однократной синхронизации — локальную папку и URL сервера — не указывайте. После завершения настройки команда завершает работу.

Параметр

По умолчанию

Описание

--userid <user>

Обязательно

ID пользователя для создаваемой учётной записи.

--serverurl <url>

Обязательно

Базовый URL сервера Nextcloud, например https://cloud.example.com.

--apppassword <password>

Не задано

Пароль приложения для учётной записи. Если не указан, учётная запись сохраняется, а вход нужно будет выполнить позже в клиенте для ПК.

--localdirpath <path>

Предлагаемая папка

Локальная папка синхронизации. Если не указана, используется папка, предложенная мастером настройки. Существующая папка должна быть пустой. Игнорируется, если включён режим File Provider в macOS.

--remotedirpath <path>

/

Удалённая папка для нового подключения классической синхронизации. Применяется при создании локальной папки синхронизации.

--isvfsenabled <0|1>

0

Укажите 1, чтобы запросить виртуальные файлы для новой папки классической синхронизации, где это поддерживается, или 0, чтобы скачать файлы. Это не включает режим File Provider в macOS.

Например, сохраните учётную запись, а затем войдите в клиенте для ПК:

nextcloudcmd --userid carla --serverurl https://cloud.example.com --localdirpath "$HOME/Nextcloud"
